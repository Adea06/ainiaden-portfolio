THE PROJECT

This project was provided by Lambda BI Ltd through the University of Leicester’s Uniworx industry project programme. We investigated whether psychological market factors could improve financial prediction.

Within a group of four MSc Data Science students, I independently built the LightGBM classification model, explainability analysis and Streamlit dashboard. I then reworked the dashboard around an investor’s needs.

How could an investor compare the technical baseline with behavioural information without being encouraged to blindly trust the model?

DISCOVER

The first dashboard translated the model out of notebooks, but it was still shaped around the analysis rather than the investor. It was multi-page, scroll-heavy and made users work to answer four basic questions:

  • Did behavioural information actually improve the prediction?
  • How confident was the model?
  • What evidence shaped the result?
  • Would the model transfer to another market?
How might I help an investor understand a model signal without encouraging blind trust in it?
DEFINE

I used the modelling process as product discovery and kept two comparable stages:

STAGE 1

Technical indicators only

Price, volume, momentum, trend and volatility.

STAGE 2

Technical + behavioural

News sentiment, VIX and engineered rolling features.

This made the behavioural contribution visible rather than assumed.

REAL-WORLD CONSTRAINT

The original dashboard did not have a validated live-news pipeline. I therefore avoided presenting Stage 2 as a fully live prediction. Price and technical context can support current views, but new behavioural predictions require the same timestamped news → sentiment pipeline used during training.

Richer behavioural model↔Reliable live dataClarity and reliability over feature completeness.
EVIDENCE

Make the evidence available without overwhelming the decision.

Model evaluation informed the interface: direction, probability and supporting context have distinct roles. The detailed research remains available for readers who want to inspect the findings.

TEST

What the project established

  • Behavioural features improved LightGBM directional F1 in both original markets.
  • Stage comparison made the behavioural contribution inspectable.
  • External testing exposed transfer limitations.
  • The redesign consolidated comparison and context into one view.

What I still need to test

  • Whether investors interpret probability correctly.
  • Whether the interface improves decision understanding.
  • Which language creates better-calibrated trust.

The model was evaluated. The redesigned experience still needs usability testing.

RESPONSIBLE DESIGN

This is decision support, not financial advice. A future iteration would replace direct BUY/SELL language with evidence-led wording:

Evidence leans positiveEvidence is mixedEvidence leans negative

I would also test “Why this signal?” explanations, chart accessibility, contrast and reduced motion.

NEXT TEST

I would run five moderated sessions with self-directed mid-term investors. Tasks would test whether participants can:

  1. Explain Stage 1 vs Stage 2.
  2. Identify whether behaviour changed direction or confidence.
  3. Interpret probability without treating it as certainty.
  4. Find the evidence behind a signal.
  5. Recognise the tool's limitations.

OPTIONAL RESEARCH DETAIL

Behind the classification model

The wider research explored both return prediction and market direction. My contribution focused on LightGBM classification and how its uncertain outputs should be communicated.

01 / Data pipeline

  1. InputsHistorical market prices, technical indicators, VIX and financial news.
  2. PrepareAlign timestamps, score news with FinBERT, and construct lagged and rolling features.
  3. CompareTrain a technical-only baseline and a technical + behavioural LightGBM model using time-based evaluation.
  4. Explain and presentEvaluate predictions, inspect SHAP contributions and present the signal with probability and context in Streamlit.

02 / Why focus on classification?

Regression in the wider research produced weak estimates of return magnitude, with negative or near-zero R². That did not support presenting an exact return estimate as a dependable answer.

The dashboard therefore focuses on direction and probability. Adding behavioural indicators to the technical baseline allowed us to test whether they improved directional classification. This is a change in the question being answered, not a guarantee of accurate prediction.

Return magnitude → Direction + probability → Supporting evidence

03 / What changed with behavioural indicators?

Held-out classification results · Stage 1 → Stage 2
MarketF1RecallROC-AUC
S&P 5000.589 → 0.6250.565 → 0.6480.396 → 0.389
FTSE 1000.268 → 0.4330.171 → 0.3240.528 → 0.481

F1 and recall improved, but ROC-AUC did not. Behavioural indicators helped some classification outcomes without establishing reliable separation of the classes. This distinction is why the interface keeps uncertainty visible.

The S&P-trained model reached 0.694 F1 in the project’s Russell 2000 external evaluation. Transfer still requires validation for each market and period.

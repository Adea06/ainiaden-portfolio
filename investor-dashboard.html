Overview

I worked on a live R&D brief from Lambda BI Ltd, sourced through Uniworx and the University of Leicester. The team of four MSc Data Science students tested whether behavioural finance indicators (news sentiment and market fear) could improve financial prediction beyond technical indicators alone.

I independently built the LightGBM classification model, the explainability analysis and the Streamlit dashboard, then redesigned the dashboard around the investor.

How can an investor compare a technical baseline with behavioural information without trusting the model blindly?

The model results are mixed, and that shaped the design: an uncertain model needs an interface that helps people calibrate their trust.

01 Discover

From model outputs to investor questions.

My first dashboard moved the model out of notebooks, but it was built around the analysis, not the investor. It spread across several pages, needed a lot of scrolling, and left four basic questions unanswered:

  • Did behavioural information improve the prediction?
  • How confident is the model?
  • What evidence shaped the result?
  • Would it work in a different market?

These are hypotheses from reviewing my own interface and the model evidence. Investor testing is needed to validate them.

Design constraint

There was no validated live-news pipeline, so I didn't present the behavioural model as a live prediction. Price and technical context can support current views, but a new behavioural prediction needs the same news-to-sentiment process used in training. I chose clarity and reliability over feature completeness.

Optional research detail

Behind the classification model

The wider research explored both return prediction and market direction. My contribution focused on LightGBM classification and how its uncertain outputs should be communicated.

How to read the metrics: F1 balances catching real cases against false alarms. Recall is the share of actual cases the model caught. ROC-AUC measures how well the model separates the two outcomes, where 0.5 is no better than chance. PR-AUC measures precision against recall and should be read relative to how common the positive class is.

01 / Data pipeline

  1. InputsHistorical market prices, technical indicators, VIX and financial news.
  2. PrepareAlign timestamps, score news with FinBERT, and construct lagged and rolling features.
  3. CompareEvaluate technical-only and technical + behavioural LightGBM models using time-based evaluation. S&P 500 models used GridSearch; FTSE 100 models used Optuna.
  4. Explain and presentEvaluate predictions, inspect SHAP contributions and present the signal with probability and context in Streamlit.

02 / Why focus on classification?

Regression in the wider research produced weak estimates of return magnitude, with negative or near-zero R². That did not support presenting an exact return estimate as a dependable answer.

The dashboard therefore focuses on direction and probability. Adding behavioural indicators to the technical baseline allowed us to test whether they improved directional classification. This is a change in the question being answered, not a guarantee of accurate prediction.

Return magnitude → Direction + probability → Supporting evidence

F1 improved in both markets, but ROC-AUC fell in both and FTSE 100 PR-AUC fell slightly. The S&P 500 gains are small and come from a single test split. Behavioural indicators changed the model's predictions without clearly improving its ability to rank them, so I designed the interface to help investors question the signal, not accept it.

The S&P-trained model reached 0.694 F1 on Russell 2000 data. Treat this as an initial check, not proof of transfer.
